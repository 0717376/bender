# Навык: Вики

Личная база знаний — markdown-файлы в рабочей директории.

- Перед ответом ищи по файлам (`Grep`, `Glob`) и читай нужные страницы (`Read`). Не
  выдумывай того, чего нет в вики — если не нашёл, так и скажи.
- Создавай и правь страницы по просьбе: `Edit` для точечных правок, `Write` для новых
  файлов. Пиши чистый, аккуратный markdown. Первая строка страницы — заголовок `# ...`:
  из него берётся человеческое имя страницы в интерфейсе.
- Помогай с организацией (переименовать, разбить, объединить страницы) аккуратно. Для
  крупной реорганизации можно делегировать субагенту `librarian` через `Task`.

## Иерархия страниц

Папки отдельной сущностью не считаются: папка с `index.md` — это одна страница со своими
детьми, как в Confluence. `infra/machines/index.md` — это страница «Машины», а
`infra/machines/main.md` — её ребёнок.

- Чтобы у страницы `x.md` появились дети, её нужно продвинуть: `x.md` → `x/index.md`,
  и дальше писать детей в `x/`. Ссылки на неё при этом придётся поправить.
- Имена файлов — латиницей, нижним регистром, через дефис (`home-network.md`,
  `giga-vpn.md`). Имя файла — идентификатор: он в URL и во всех ссылках. Заголовок внутри
  страницы правится свободно, имя файла за ним не тянется.

## Ссылки

Ссылайся на страницы по имени: `[[litellm]]` или с подписью `[[litellm|наш прокси]]`.
Имя ищется по всей вики, поэтому страница может переехать между родителями — ссылка
не сломается. Раздел внутри страницы: `[[litellm#доступ]]`.

Обычные markdown-ссылки `[текст](путь.md)` тоже работают, но при переносе страницы
их приходится чинить руками — предпочитай `[[имя]]`.

## Удаление

Страницы не стирай. Если пользователь просит удалить — перемести в корзину:
`mv страница.md .trash/`. Так удаление можно отменить.

Если запрос на самом деле про дела/напоминания/планы — переключись на навык `tasks`.
