# Настройка и эксплуатация

[English version](configuration.md)

Читать это необязательно: `./install.sh` спросит то, что важно, и сам напишет `.env`.
Здесь — то, о чём мастер не спрашивает, и то, как со стендом жить дальше.

## Команда `bender`

```
./bender doctor            проверить стенд: контейнеры, авторизация, бот, порты, диск
./bender update            git pull, свежие образы, перезапуск, проверка
./bender update --check    только посмотреть, вышло ли что-то новое
./bender rollback          вернуться на версию, что работала до последнего обновления
./bender pair [--reset]    код привязки Telegram
./bender token             выпустить новый долгоживущий токен Claude и записать в .env
./bender logs [сервис]     смотреть логи
./bender up | down | restart | version
```

`update` и `up` всегда перезапускают фронтенды. Их nginx определяет IP контейнера
бэкенда один раз, при старте, и запоминает: пересоберёшь бэкенд без их рестарта —
и все страницы отвечают 502.

## Авторизация

Агент ходит в Claude по подписке, через Claude CLI. Кредов бывает два вида:

- **Долгоживущий токен** — `claude setup-token` выдаёт его на год, он ложится в `.env`
  как `CLAUDE_CODE_OAUTH_TOKEN`. На сервере это единственный разумный вариант: браузер
  не нужен, перезагрузку переживает.
- **OAuth-сессия из `~/.claude`** — монтируется в контейнер. Годится для своей машины.
  На хосте без браузера она однажды перестаёт обновляться, и агент начинает отвечать
  «Failed to authenticate»; `./bender doctor` это ловит.

`./bender token` перевыпускает токен и подставляет его, ничего больше не трогая.

## Telegram

Заведите бота у [@BotFather](https://t.me/BotFather), впишите токен в `.env` и запустите
`./bender pair` — он напечатает шестизначный код. Отправьте код своему боту, и чат
привязан: id сохранится в `data/telegram.json`, без правки конфига и без перезапуска.
Код одноразовый и гаснет, как только чат привязался.

Заданный `TELEGRAM_ALLOWED_IDS` отменяет привязку совсем — настроенному серверу лишняя
дверь не нужна.

### Большие файлы (необязательно)

Облачный Bot API ограничивает файлы: 20 МБ на скачивание, 50 МБ на отправку. Сервис
`tgapi` из комплекта (официальный [telegram-bot-api](https://github.com/tdlib/telegram-bot-api))
поднимает оба предела до 2 ГБ:

1. Получите `api_id` / `api_hash` на [my.telegram.org](https://my.telegram.org) → API
   development tools (имя приложения любое; ключи опознают «приложение», доступа к
   аккаунту они не дают).
2. Добавьте в `.env`:
   ```
   TELEGRAM_API_ID=...
   TELEGRAM_API_HASH=...
   TG_API_BASE=http://tgapi:8081
   ```
3. Разлогиньте бота в облаке (разово, обратимо): `curl https://api.telegram.org/bot<TOKEN>/logOut`
4. `docker compose up -d tgapi backend`

Бэкенд видит локальный сервер по `TG_API_BASE` и читает входящие файлы прямо с общего
тома `tg-bot-api/`, не перекачивая их по HTTP. Не задавать эти переменные — всё работает
через облачный API.

## Образы: готовые или из исходников

Решает `BENDER_TAG`. `main` — готовые мультиарх-образы (amd64/arm64) из GHCR: установка
становится скачиванием вместо сборки. `local` — сборка из рабочего дерева, это то, что
нужно, если собираетесь править код. Переключают `./install.sh --source` и
`./install.sh --prebuilt`; `./bender update` следует тому, что записано в `.env`.

Образы собирает workflow `images` при каждом пуше в `main`. Если вы форкнули проект, после
первой сборки пакеты в GHCR нужно один раз сделать публичными (страница пакета → Package
settings → Change visibility), иначе `docker compose pull` попросит логин.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `WIKI_PASSWORD` | — | пароль веб-интерфейса (обязателен) |
| `CLAUDE_MODEL` | `sonnet` | модель агента (`sonnet`/`opus`/`haiku` или полный id) |
| `CLAUDE_CODE_OAUTH_TOKEN` | — | долгоживущий токен из `claude setup-token`; задан — используется вместо сессии в `~/.claude` |
| `CLAUDE_DIR` / `CLAUDE_JSON` | `~/.claude` / `~/.claude.json` | креды Claude CLI, монтируются в контейнер |
| `TELEGRAM_BOT_TOKEN` | — | токен бота; пусто — бот выключен |
| `TELEGRAM_ALLOWED_IDS` | — | список chat id через запятую; пусто — привязка по коду |
| `TG_API_BASE` | `https://api.telegram.org` | адрес локального bot-api (см. выше) |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | — | ключи my.telegram.org для сервиса `tgapi` |
| `FILES_MAX_UPLOAD` | `524288000` | предел загрузки через веб, байты |
| `ASR_UPSTREAM` | — | адрес сервиса распознавания речи для голосовых |
| `ASR_MODEL` | `gigaam-rnnt` | model_id, который передаётся сервису распознавания |
| `SESSION_FRESH_HOURS` | `6` | простой, после которого начинается свежая сессия |
| `REVIEWER_ENABLED` / `REVIEWER_MODEL` | `1` / `sonnet` | фоновый ревьюер памяти и навыков |
| `CURATOR_ENABLED` / `CURATOR_INTERVAL_HOURS` | `1` / `168` | куратор библиотеки навыков |
| `WIKI_PORT` / `TASKS_PORT` / `BOOKS_PORT` | `8842` / `8851` / `8899` | порты интерфейсов |
| `BENDER_TAG` | `local` | `main` — готовые образы из GHCR, `local` — сборка из исходников |
| `TZ` | `Europe/Moscow` | таймзона (по ней срабатывает крон) |

## Установка руками

```bash
git clone https://github.com/0717376/bender && cd bender
cp .env.example .env && $EDITOR .env
mkdir -p content data files books tg-bot-api
docker compose up -d --build
```

Две вещи, которые мастер делает, а руками про них забывают: завести каталоги данных до
того, как их создаст Docker от root, и убедиться, что `~/.claude.json` существует именно
*файлом* — если файла нет, Docker подставит на его место каталог, и CLI сломается молча.

## Если что-то не так

Начинайте с `./bender doctor` — он называет сломанную часть. Дальше:

- **502 на всех страницах** — фронтенды держат старый IP бэкенда: `./bender restart`.
- **«Failed to authenticate» в чате** — протух токен: `./bender token`.
- **Бот молчит** — смотрите `doctor`: он дёргает `getMe` и говорит, привязан ли чат.
- **Совсем ничего** — `./bender logs backend`.

Данные (`content/`, `data/`, `files/`, `books/`) лежат на диске рядом с репозиторием,
ни обновление, ни откат их не трогают.
